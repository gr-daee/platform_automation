# Authoring & Updating DAEE User Guides

> **The end-to-end guide for adding or changing a documentation page.** How the docs system fits
> together, the exact steps to author a page, capture its screenshots, register it in the nav, preview
> it, and sync it to the app — plus the gotchas that have bitten us.

> **Audience:** Internal (docs maintainers / engineers) · **Status:** 🟢 Authored
> **Companion docs:** [`_TEMPLATE.md`](./_TEMPLATE.md) (page skeleton) · [`CAPTURE-HARNESS.md`](./CAPTURE-HARNESS.md) (screenshot deep-dive) · [`MODULE-MAP.md`](./MODULE-MAP.md) (module index)

---

## 1. How the system fits together

`platform_automation` is the **canonical source** for all DAEE docs. The app (`web_app`) is a **downstream
mirror** — content only ever flows **platform_automation → web_app**, never the reverse.

```
platform_automation (SOURCE OF TRUTH)                 web_app (MIRROR — rendered app)
────────────────────────────────────────             ───────────────────────────────────────
docs/user-guides/<module>/*.md          ── copy ──▶   src/content/docs/user-guides/<module>/*.md
docs/user-guides/assets/<module>/*.png  ── copy ──▶   public/docs-assets/<module>/*.png
scripts/docs/build-site.mjs  (nav maps) ── mirror ─▶  src/app/documentation/_lib/nav.ts
                                                      └─ gen-content.mjs inlines *.md → _lib/content-data.ts
scripts/docs/capture.mjs  (screenshots)               (renders /documentation/<route>)
docs/site/index.html      (local preview)
```

| Thing | Where | What it is |
|---|---|---|
| **Guide pages** | `docs/user-guides/<module>/*.md` | The markdown you author |
| **Screenshots** | `docs/user-guides/assets/<module>/*.png` | Generated by the capture harness |
| **Nav & routes** | `scripts/docs/build-site.mjs` | `DOC_ROUTE`, `NAV_LABEL`, `MODULES`/`MASTER`, `SUBPAGES` |
| **Capture harness** | `scripts/docs/capture.mjs` (`npm run docs:capture`) | Shoots screenshots against staging |
| **Local preview site** | `docs/site/index.html` (`npm run docs:site`) | Self-contained HTML preview |
| **Credentials** | `.env` (`TEST_BASE_URL`, `IACS_MD_USER_*`) + `e2e/.auth/iacs-md.json` | Staging login for capture |

## 2. The update pipeline at a glance

```
1. Write / edit the .md        (§3)
2. Add image slots + directives (§4)
3. Register the page in nav      (§5)   ← new pages only
4. Capture screenshots           (§6)
5. Preview locally               (§7)
6. Sync to web_app               (§8)
7. Verify                        (§9)
```

Steps 1–5 are all in **platform_automation**. Step 6 is the only one that touches `web_app`.

---

## 3. Write or edit the markdown

- **New page:** copy [`_TEMPLATE.md`](./_TEMPLATE.md) to `docs/user-guides/<module>/<name>.md` and fill it in.
  Match the house style of a sibling page (e.g. `finance/README.md`, `o2c/order-to-cash.md`).
- **Existing page:** edit in place — **prefer updating an existing page over creating a near-duplicate.**

**House-style essentials**
- A one-line **intro blockquote**, then a **metadata blockquote**:
  ```md
  > **Audience:** Customer + Internal · **Module:** `/route` · **Status:** 🟢 Authored
  > **Verified:** against `web_app/src/app/<area>` on <date>.
  ```
- **Internal-only content** goes inside `<!-- INTERNAL:START -->` … `<!-- INTERNAL:END -->` (table names,
  edge-fn names, permissions, open gaps). The renderer's Customer/Internal toggle hides these for customers.
- Standard sections: *What you can do · Before you begin · Step-by-step · Common mistakes · Related · Support*.
- **Don't invent behaviour.** Verify every workflow claim against code (routes, actions, statuses) before
  writing it. If unsure, label it clearly.

## 4. Image slots + capture directives

A screenshot is **two consecutive lines**: an image slot, then a capture directive **immediately after
it** (no blank line between). The harness only captures a directive that has an image line directly above.

```md
![<alt text>](../assets/<module>/<name>.png)
<!-- capture: { "project": "<persona>", "route": "/<app-route>" } -->
```
*(e.g. `../assets/o2c/sr-01-list.png` + route `/o2c/sales-returns`, persona `iacs-md`.)*

- **`route`** — the app route to shoot (required). **`project`** — the persona (`iacs-md`, required).
- **`action`** (optional) — a scripted interaction before the shot: `open-create-dialog`,
  `open-first-<row>`, `click-tab` (needs `"section"`), `open-create-warehouse/company`, etc. See the
  `ACTIONS` registry in `scripts/docs/capture.mjs`. If an action fails, the harness falls back to a
  plain route shot (never crashes).

**Asset path convention** — the path in `![]()` is resolved **relative to the .md file**, and the app
rewrites anything after `assets/` to `/docs-assets/`:
- Page in `docs/user-guides/<module>/foo.md` → use `../assets/<module>/pic.png`.
- **Top-level page** in `docs/user-guides/foo.md` (e.g. `address-book.md`) → use `assets/<module>/pic.png`
  (no `../`), so it still writes into `docs/user-guides/assets/<module>/`.

> ⚠️ **A capture directive with no image line above it is silently never captured** — the page renders
> with no screenshot. This is the #1 authoring bug. The verifier in §9 catches it.

## 5. Register the page in the nav (new pages only)

Edit `scripts/docs/build-site.mjs` and add the file in **three** maps (four if it's a top-level module):

```js
// DOC_ROUTE — file → app route
'user-guides/o2c/sales-returns.md': '/o2c/sales-returns',
// NAV_LABEL — file → sidebar label
'user-guides/o2c/sales-returns.md': 'Sales Returns',
// SUBPAGES — indented under a parent module route
'/o2c': ['user-guides/o2c/sales-returns.md', 'user-guides/o2c/back-orders.md'],
// MODULES or MASTER — only if it's a NEW top-level module/master-data entry
{ route: '/address-book', label: 'Address Book' },
```

Also add it to [`MODULE-MAP.md`](./MODULE-MAP.md), and to the **Master data** table in
[`README.md`](./README.md) if it's master data. (The `web_app` nav mirror is updated in §8.)

## 6. Capture the screenshots (against staging)

Full detail is in [`CAPTURE-HARNESS.md`](./CAPTURE-HARNESS.md); the working recipe:

```bash
# .env must contain (exact names):
#   TEST_BASE_URL=https://staging.daee.in
#   IACS_MD_USER_EMAIL=...  IACS_MD_USER_PASSWORD=...  IACS_MD_USER_TOTP_SECRET=<base32>
set -a; . ./.env; set +a          # Playwright loads .env.local (absent), so export .env yourself

# 1. Refresh the login session (the stored one expires after ~2 weeks)
npx playwright test --project=setup          # writes e2e/.auth/iacs-md.json via email+password+TOTP

# 2. Capture — target just your new/changed routes with --match (comma-separated substrings)
npm run docs:capture -- --match /o2c/sales-returns,/o2c/back-orders

# Flags: --route-only (skip actions) · --persona iacs-md · --match <route,route>
```

- **Always visually check the output PNGs** — open them and confirm they show the real screen (not a
  login page, empty state, or half-loaded skeleton). A green `✓` only means a file was written.
- Screenshots are **viewport-framed** (1440×900): content below the fold isn't captured. Pick a route/
  action that puts the subject in view.
- The harness redacts PII (emails/phones/GSTIN/PAN/Aadhaar) automatically; it does **not** change the
  tenant logo or names.

## 7. Preview locally

```bash
npm run docs:site        # regenerates docs/site/index.html
```
Open `docs/site/index.html` in a browser. It reports **"Soon"** for any route whose page isn't mapped —
a quick check that your nav registration (§5) is correct.

## 8. Sync to web_app (the downstream mirror)

Do this only after the platform_automation side is complete and verified. Work on the **`documentation`**
branch of `web_app`.

```bash
cd ../web_app
git checkout documentation                    # docs mirror + pipeline live here

# 1. Copy changed markdown  (docs/user-guides/… → src/content/docs/user-guides/…)
cp ../platform_automation/docs/user-guides/o2c/sales-returns.md src/content/docs/user-guides/o2c/

# 2. Copy screenshots  (docs/user-guides/assets/<m>/ → public/docs-assets/<m>/)
cp ../platform_automation/docs/user-guides/assets/o2c/*.png public/docs-assets/o2c/

# 3. Mirror the nav entries into src/app/documentation/_lib/nav.ts
#    (same DOC_ROUTE / NAV_LABEL / SUBPAGES additions you made in build-site.mjs)

# 4. Regenerate the inlined content + verify + commit
npm run docs:gen            # = node scripts/docs/gen-content.mjs  (inlines *.md → _lib/content-data.ts)
npm run check:all           # types + lint — MUST pass (content-data.ts is committed, not built)
git add src/content/docs public/docs-assets src/app/documentation/_lib
git commit && git push origin documentation
```

> **`content-data.ts` is generated and committed.** `next build` does **not** regenerate it — always run
> `npm run docs:gen` and commit the result, or the app shows stale content.

## 9. Verify (before you call it done)

Run the parity/link checks — these catch the real defects:

- **Every `![]()` slot has a PNG on disk** (no broken images).
- **Every `<!-- capture -->` has an image line directly above it** (no silently-uncaptured directives).
- **Internal `.md` links resolve**, and **`#anchor` links match the renderer's slug** (see §10).
- **`npm run docs:site`** shows no `"Soon"` for your page (nav is wired).
- **After sync:** platform_automation `.md`/PNG == web_app copy (byte-identical); `npm run check:all` passes.

A scriptable check lives in the session notes; the essential greps:
```bash
# broken double-hyphen anchors (see §10)
grep -rnoE '#[a-z0-9-]*--[a-z0-9-]*\)' docs/user-guides
# capture directives with no preceding image line = silently uncaptured
```

## 10. Slug / anchor rules (a real gotcha)

In-page links (`…#section`) must match the app renderer's slug algorithm
(`web_app/src/app/documentation/_components/MarkdownDoc.tsx`):

```
lowercase → strip everything except [a-z0-9 space hyphen] → trim → collapse whitespace runs to ONE '-'
```

So `&`, `—` (em-dash), `,`, and `()` are **removed**, and the surrounding spaces collapse to a **single**
hyphen — **not** a double one:

| Heading | Correct anchor |
|---|---|
| `## Credit Memos & Debit Notes` | `#credit-memos-debit-notes` |
| `## Pricing, invoice & E-Way Bill` | `#pricing-invoice-e-way-bill` |
| `## Cash Receipts — record and apply` | `#cash-receipts-record-and-apply` |
| `## Early-Payment Discount (EPD)` | `#early-payment-discount-epd` |

> A `--` (double hyphen) in an anchor link is almost always a bug — the target won't scroll into view.

## 11. Rules & gotchas checklist

- ✅ **Don't invent workflow behaviour** — verify against code first; label uncertainty.
- ✅ **Capture directive must sit directly under an image line** (§4).
- ✅ **Top-level pages use `assets/…`, sub-pages use `../assets/…`** (§4).
- ✅ **Single-hyphen anchors** (§10).
- ✅ **`<!-- INTERNAL -->` blocks** for table/edge-fn/permission/gap detail.
- ✅ **Verify captured PNGs visually** — a `✓` isn't proof (§6).
- ✅ **Regenerate + commit `content-data.ts`** on the web_app side (§8).
- ✅ **Register new pages in all nav maps** (§5) — an unmapped page shows `"Soon"`.
