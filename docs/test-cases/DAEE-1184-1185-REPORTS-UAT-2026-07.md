## How to Use This Document

- Every row has a **Test ID**. Report pass/fail by Test ID + tenant + date window used.
- Cases are grouped by feature area. Run Part 1 before Parts 2 – 4 (setup depends on Part 1 output).
- Where a case exercises a race that cannot be forced (e.g. `dedupeKey` telemetry), execution is optional; note "N/A — not forced" instead of skipping silently.
- Every case lists an **explicit expected result** and, where useful, an SQL / grep cross-check for the tester or reviewer.

### 2D · C-2 amended · Dealer Advance Status columns

| Test ID | Precondition | Action | Expected |
|---|---|---|---|
| CR-UAT-013 | Same | Open **Dealer Advance Status** tab | Columns in order: *Dealer Code, Business Name, Region, Territory, City, **Converted to Advance**, **Applied to Invoice**, **Available Advance Balance***. Subtitle explicitly says the first two are period-scoped and the third is point-in-time. |
| CR-UAT-014 | Dealer with `amount_converted_to_advance > 0` on any period receipt | Verify Column 1 | `Converted to Advance = SUM(amount_converted_to_advance)` for that dealer's period receipts. |

| CR-UAT-016 | Dealer with an active advance | Verify Column 3 | `Available Advance Balance = SUM(dealer_advances.available_balance)` on `status IN ('available','partially_used')` at the moment of report generation (point-in-time, not period-scoped). |
| CR-UAT-017 | Same | Export XLSX → **Dealer Advance Status** sheet | Same three amount columns in the same order with the same labels. Footer TOTAL row sums all three. |
